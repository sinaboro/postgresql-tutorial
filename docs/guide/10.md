## 윈도우 함수란

```
함수() OVER (
    PARTITION BY 그룹 기준     -- 어떤 행끼리 묶어 계산할지 (생략하면 전체)
    ORDER BY 정렬 기준         -- 묶음 안에서의 순서 (순위·누적에 필요)
    ROWS BETWEEN ... AND ...   -- 계산에 포함할 범위(프레임)
)
```

GROUP BY 는 그룹마다 **한 행으로 줄이지만**, 윈도우 함수는 **모든 행을 그대로 두고** 각 행 옆에 계산 결과를 붙입니다. “각 직원의 연봉과 부서 평균을 함께 보기” 처럼 상세와 집계를 동시에 볼 때 씁니다.

## 누적 합과 비중

`sum(x) OVER (ORDER BY 월)` 은 처음부터 현재 행까지의 합(누적)이고, `sum(x) OVER ()` 는 전체 합입니다.

## LAG / LEAD - 이전·다음 행

| 함수 | 의미 |
|---|---|
| `LAG(x [, n [, 기본값]])` | n 행 앞(기본 1)의 x |
| `LEAD(x [, n [, 기본값]])` | n 행 뒤의 x |
| `FIRST_VALUE(x)` / `LAST_VALUE(x)` | 프레임의 처음/마지막 값 |

## 윈도우 프레임과 이동 평균

ORDER BY 가 있는 윈도우의 기본 프레임은 “처음부터 현재 행까지” 입니다. `ROWS BETWEEN 2 PRECEDING AND CURRENT ROW` 처럼 바꾸면 최근 3행의 평균, 즉 **이동 평균**이 됩니다.

> [!WARN] LAST_VALUE 의 함정
> 10-09 에서 프레임을 지정하지 않으면 기본 프레임이 “현재 행까지” 라서 LAST_VALUE 가 **현재 행 자신**을 돌려줍니다. 그래서 `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING` 으로 전체를 지정했습니다. 수강생이 가장 많이 틀리는 부분이니 프레임을 빼고 실행해 차이를 직접 보여 주세요.

## 정리

- 윈도우 함수는 행을 유지하면서 그룹 계산 결과를 붙인다.
- 순위 3종의 차이는 동점 처리. TOP-N 은 서브쿼리로 감싸서 거른다.
- 누적은 `sum() OVER (ORDER BY)`, 전월 대비는 `LAG`, 이동 평균은 `ROWS BETWEEN`.
