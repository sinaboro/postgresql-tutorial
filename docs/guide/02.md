# 02장 ∙ 테이블 만들기 - 자료형과 제약 조건

## 학습 목표

- `CREATE TABLE` 로 테이블을 만들고 `\d` 로 구조를 확인할 수 있다.
- 숫자·문자·날짜·논리 자료형의 차이를 알고 알맞게 고를 수 있다.
- PRIMARY KEY, NOT NULL, UNIQUE, CHECK, DEFAULT, FOREIGN KEY 제약 조건을 설정할 수 있다.
- `ALTER TABLE` 로 구조를 바꾸고 `TRUNCATE` 와 `DROP` 의 차이를 설명할 수 있다.

## 자주 쓰는 자료형

| 분류 | 자료형 | 설명 | 사용 예 |
|---|---|---|---|
| 정수 | `SMALLINT` / `INTEGER` / `BIGINT` | 2 / 4 / 8바이트 정수 | 수량, ID (큰 테이블은 BIGINT) |
| 정확한 소수 | `NUMERIC(p, s)` | 전체 p자리, 소수 s자리. 오차 없음 | **금액**, 환율, 비율 |
| 근사 실수 | `REAL` / `DOUBLE PRECISION` | 부동소수점, 계산 오차 있음 | 과학 측정값, 좌표 |
| 문자 | `VARCHAR(n)` / `TEXT` / `CHAR(n)` | 가변(최대 n) / 무제한 / 고정 길이 | 이름, 본문 |
| 날짜·시간 | `DATE` / `TIMESTAMP` / `TIMESTAMPTZ` | 날짜 / 날짜+시간 / 시간대 포함 | 생일 / 주문일시 / 로그 |
| 기간 | `INTERVAL` | 시간 간격 | '3 days', '2 hours' |
| 논리 | `BOOLEAN` | true / false / NULL | 사용 여부 |
| 기타 | `UUID`, `JSONB`, 배열(`TEXT[]`) | 고유 ID, 반정형 데이터, 목록 | 16장 |

> [!TEACH] 자료형 설명 요령
> - `VARCHAR(n)` 과 `TEXT` 는 PostgreSQL 에서 **성능 차이가 없습니다.** 길이 제한이 업무 규칙일 때만 `VARCHAR(n)` 을 쓰면 된다고 설명합니다. (다른 DBMS 경험자가 자주 묻습니다.)
> - `CHAR(n)` 은 남는 자리를 공백으로 채우므로 실무에서 거의 쓰지 않습니다. 예제의 `char_len` 결과(2)와 `[ab]` 처럼 비교·연결할 때는 뒤 공백이 무시된다는 점이 오히려 혼란을 줍니다.
> - `TIMESTAMPTZ` 는 저장할 때 UTC 로 바꿔 두고, 보여 줄 때 세션의 timezone(한국 설치는 Asia/Seoul)으로 변환합니다. 여러 나라 사용자가 있는 서비스라면 TIMESTAMPTZ 를 권장합니다.

### 금액은 반드시 NUMERIC

`0.1 + 0.2` 는 이진 부동소수점으로 정확히 표현되지 않아 `0.3` 과 다릅니다. 돈 계산에 `REAL`/`DOUBLE PRECISION` 을 쓰면 원 단위 오차가 누적됩니다.

## 제약 조건 (Constraint)

제약 조건은 **잘못된 데이터가 들어오는 것을 DB 가 막아 주는 규칙**입니다. 애플리케이션 코드에서 검사하더라도 DB 에 한 번 더 걸어 두는 것이 원칙입니다(코드는 여러 개, DB 는 하나).

| 제약 조건 | 의미 | 위반 시 |
|---|---|---|
| `PRIMARY KEY` | 행을 유일하게 식별 (= UNIQUE + NOT NULL), 테이블당 1개 | duplicate key 오류 |
| `NOT NULL` | 값 필수 | null value 오류 |
| `UNIQUE` | 중복 불가 (NULL 은 여러 개 허용) | duplicate key 오류 |
| `CHECK (조건)` | 조건식이 참이어야 함 | check constraint 오류 |
| `DEFAULT 값` | 값을 생략하면 넣을 기본값 | (제약이라기보다 기본값) |
| `REFERENCES 부모(컬럼)` | 외래 키, 부모 테이블에 존재하는 값만 허용 | foreign key 오류 |

> [!NOTE] IDENTITY - 자동 증가 번호
> `GENERATED ALWAYS AS IDENTITY` 는 SQL 표준 방식의 자동 증가 컬럼입니다. 예전 방식인 `SERIAL` 보다 권장됩니다(12장에서 차이를 실습). `ALWAYS` 는 사용자가 값을 직접 넣지 못하게 막고, `BY DEFAULT` 는 직접 넣는 것도 허용합니다. 실습 DB 는 샘플 데이터를 번호까지 지정해서 넣기 위해 `BY DEFAULT` 를 씁니다.

## 외래 키(FOREIGN KEY)와 참조 무결성

학생-수강-과목처럼 **N:M 관계**는 가운데에 연결 테이블(`enrollments`)을 두고 양쪽을 외래 키로 참조합니다. 연결 테이블의 기본 키는 두 외래 키를 합친 **복합 기본 키**가 자연스럽습니다.

@@ex 02-07 02-08

부모 행을 지울 때의 동작은 `ON DELETE` 옵션으로 정합니다.

| 옵션 | 부모 삭제 시 자식은 | 쓰임새 |
|---|---|---|
| `NO ACTION` / `RESTRICT` (기본) | 자식이 있으면 삭제 거부 | 대부분의 경우 (실수 방지) |
| `CASCADE` | 자식도 함께 삭제 | 주문 → 주문상세처럼 부모 없이는 의미 없는 자식 |
| `SET NULL` | 자식의 FK 를 NULL 로 | 담당자 퇴사 시 담당자 비우기 |
| `SET DEFAULT` | 자식의 FK 를 기본값으로 | 드묾 |

@@ex 02-09

> [!WARN] CASCADE 는 신중하게
> `ON DELETE CASCADE` 는 편리하지만 고객 한 명을 지웠는데 주문·리뷰·포인트 내역이 연쇄로 사라질 수 있습니다. shop 스키마에서는 `order_items → orders` 에만 CASCADE 를 썼고, `orders → customers` 는 기본값(거부)입니다. 3장 예제 03-10 에서 직접 확인합니다.

## 구조 변경 - ALTER TABLE

| 작업 | 문법 |
|---|---|
| 컬럼 추가 | `ALTER TABLE t ADD COLUMN c 자료형 [제약]` |
| 컬럼 삭제 | `ALTER TABLE t DROP COLUMN c` |
| 자료형 변경 | `ALTER TABLE t ALTER COLUMN c TYPE 새자료형 [USING 변환식]` |
| NOT NULL 설정/해제 | `ALTER TABLE t ALTER COLUMN c SET NOT NULL` / `DROP NOT NULL` |
| 기본값 | `ALTER TABLE t ALTER COLUMN c SET DEFAULT 값` |
| 이름 변경 | `ALTER TABLE t RENAME COLUMN a TO b` / `RENAME TO 새테이블명` |
| 제약 추가/삭제 | `ALTER TABLE t ADD CONSTRAINT 이름 ...` / `DROP CONSTRAINT 이름` |

## 데이터 삭제 vs 테이블 삭제

| 명령 | 지우는 것 | 되돌리기 | 속도 |
|---|---|---|---|
| `DELETE FROM t` | 행 (조건 가능) | 트랜잭션 안이면 ROLLBACK 가능 | 행마다 처리 → 느림 |
| `TRUNCATE t` | 모든 행 (구조 유지) | PostgreSQL 은 트랜잭션 안이면 ROLLBACK 가능 | 매우 빠름 |
| `DROP TABLE t` | 테이블 자체 | 트랜잭션 안이면 ROLLBACK 가능 | 빠름 |

> [!QA] 예상 질문
> - **Q. 제약 조건 이름은 꼭 지어야 하나요?** 생략하면 `members_email_key` 처럼 자동으로 붙습니다. 오류 메시지에 이름이 나오므로 팀 규칙(예: `chk_테이블_내용`)을 정해 직접 짓는 것이 좋습니다.
> - **Q. PRIMARY KEY 로 주민번호·이메일 같은 실제 값을 써도 되나요?** 바뀔 수 있는 값(이메일)이나 민감한 값(주민번호)은 피하고, 의미 없는 대리 키(IDENTITY)를 PK 로, 실제 값은 UNIQUE 로 두는 것이 일반적입니다.
> - **Q. 이미 데이터가 있는 테이블에 NOT NULL 컬럼을 추가하면?** 기존 행에 넣을 값이 없어 오류가 납니다. `ADD COLUMN c INT NOT NULL DEFAULT 0` 처럼 기본값을 함께 주면 됩니다.

## 정리

- 자료형은 “어떤 값을 담을지”, 제약 조건은 “어떤 값을 거부할지”를 정한다.
- 금액은 `NUMERIC`, ID 는 `IDENTITY`, 문자열은 `TEXT` 또는 `VARCHAR(n)`.
- 외래 키는 관계를 보장하고, `ON DELETE` 로 부모 삭제 시 동작을 정한다.
