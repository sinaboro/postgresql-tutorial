## 조인의 원리

주문(orders)에는 고객 번호(`customer_id`)만 있고 고객 이름은 customers 에 있습니다. **JOIN 은 두 테이블에서 조건(ON)이 맞는 행끼리 옆으로 이어 붙이는 연산**입니다.

```
SELECT ...
FROM   A
[INNER | LEFT | RIGHT | FULL] JOIN B ON A.키 = B.키
JOIN   C ON ...
```

| 조인 | 결과에 남는 행 | 짝이 없을 때 |
|---|---|---|
| `INNER JOIN` (= `JOIN`) | 양쪽 모두 짝이 있는 행 | 버림 |
| `LEFT [OUTER] JOIN` | 왼쪽 테이블의 모든 행 | 오른쪽 컬럼을 NULL 로 |
| `RIGHT [OUTER] JOIN` | 오른쪽 테이블의 모든 행 | 왼쪽 컬럼을 NULL 로 |
| `FULL [OUTER] JOIN` | 양쪽 모든 행 | 없는 쪽을 NULL 로 |
| `CROSS JOIN` | 모든 조합 (행 수 = A × B) | 조건 없음 |

> [!TEACH] 벤 다이어그램보다 “표 두 장 붙이기”
> 조인을 벤 다이어그램으로만 설명하면 “행이 늘어나는” 현상(1:N 조인)을 이해하지 못합니다. 화이트보드에 employees 5행, departments 3행을 그리고 손으로 짝을 이어 결과표를 만들어 보이세요. 부서 없는 직원(권나래), 직원 없는 부서를 일부러 넣어 두면 OUTER JOIN 설명이 자연스럽게 이어집니다.

> [!WARN] NATURAL JOIN 은 쓰지 않는다
> 07-12 의 NATURAL JOIN 은 `dept_id` 뿐 아니라 우연히 이름이 같은 `name` 컬럼까지 조건으로 써서 0건이 되었습니다. 나중에 테이블에 같은 이름의 컬럼이 추가되면 쿼리 결과가 조용히 바뀝니다. `USING (컬럼)` 은 조인 컬럼을 명시하므로 써도 괜찮습니다.

> [!QA] 예상 질문
> - **Q. JOIN 순서가 성능에 영향을 주나요?** INNER JOIN 은 옵티마이저가 순서를 알아서 정합니다. 13장 EXPLAIN 에서 확인합니다. OUTER JOIN 은 순서에 따라 결과가 달라지므로 의미대로 써야 합니다.
> - **Q. `FROM a, b WHERE a.id = b.id` 와 JOIN 은 같은가요?** INNER JOIN 과 결과가 같은 옛 문법입니다. 조인 조건을 빠뜨리면 CROSS JOIN 이 되는 위험이 있어 명시적 JOIN 을 권장합니다.

## 정리

- INNER 는 짝이 있는 행만, LEFT 는 왼쪽 전체 + 짝 없으면 NULL.
- 1:N 조인 후 집계할 때는 `count(DISTINCT ...)` 로 중복을 주의.
- LEFT JOIN 의 오른쪽 테이블 조건은 ON 에 둔다.
