## 뷰 (VIEW)

뷰는 **이름을 붙여 저장한 SELECT 문**입니다. 데이터를 따로 저장하지 않고, 조회할 때마다 원래 쿼리를 실행합니다.

| 용도 | 예 |
|---|---|
| 복잡한 조인 재사용 | `v_order_detail` – 주문·고객·상품을 미리 조인 |
| 보안 | `v_customer_public` – 이메일·전화번호를 뺀 뷰에만 권한 부여(17장) |
| 호환성 | 테이블 구조가 바뀌어도 뷰 이름과 컬럼을 유지해 기존 프로그램 보호 |

## 머티리얼라이즈드 뷰

| 구분 | 뷰 | 머티리얼라이즈드 뷰 |
|---|---|---|
| 저장 | 쿼리만 저장 | **결과를 디스크에 저장** |
| 조회 속도 | 원본 쿼리만큼 | 테이블 조회처럼 빠름 (인덱스도 가능) |
| 최신성 | 항상 최신 | `REFRESH` 해야 갱신 |
| 용도 | 일반 재사용 | 대시보드·일별 리포트 같은 무거운 집계 |

> [!TIP] 갱신 중에도 조회하려면
> `REFRESH MATERIALIZED VIEW` 는 갱신하는 동안 조회를 막습니다. 머티리얼라이즈드 뷰에 UNIQUE 인덱스를 만들고 `REFRESH MATERIALIZED VIEW CONCURRENTLY` 를 쓰면 조회를 막지 않고 갱신합니다. 주기적 갱신은 cron 이나 pg_cron 확장으로 예약합니다.

## 시퀀스

시퀀스는 번호를 하나씩 발급하는 객체입니다. IDENTITY 컬럼도 내부적으로 시퀀스를 씁니다.

| 함수 | 설명 |
|---|---|
| `nextval('seq')` | 다음 번호를 발급 (롤백해도 되돌아가지 않음 → 번호에 빈 곳이 생길 수 있음) |
| `currval('seq')` | 이 세션에서 마지막으로 발급받은 번호 |
| `setval('seq', n)` | 현재 값을 n 으로 설정 (`setup/02_seed.sql` 마지막에서 사용) |

> [!WARN] 번호의 빈 곳은 정상
> 주문번호가 1, 2, 4 처럼 건너뛰어 수강생이 놀라는 경우가 있습니다. 실패한 INSERT 나 ROLLBACK 된 트랜잭션도 시퀀스 번호를 소비하기 때문이며 정상입니다. “빈 번호 없는 연속 번호”가 법적으로 필요한 경우(세금계산서 등)에는 별도 채번 테이블을 잠금과 함께 씁니다.

## 스키마

스키마는 데이터베이스 안의 **폴더(네임스페이스)** 입니다. 같은 DB 안에서 `report.daily_kpi`, `model.customer` 처럼 이름을 구분하고, 스키마 단위로 권한을 줄 수 있습니다. 이름 앞에 스키마를 쓰지 않으면 `search_path` 순서대로 찾습니다(기본: 사용자 이름과 같은 스키마 → public).

> [!QA] 예상 질문
> - **Q. 뷰를 쓰면 느려지나요?** 일반 뷰는 쿼리에 그대로 펼쳐져 최적화되므로 원래 쿼리와 성능이 같습니다. 뷰 위에 뷰를 여러 겹 쌓으면 불필요한 조인이 생길 수 있으니 주의합니다.
> - **Q. 뷰의 원본 테이블 컬럼을 바꾸면?** 뷰가 참조하는 컬럼은 삭제·타입 변경이 막힙니다. 뷰를 먼저 지우고(`DROP VIEW`) 다시 만들어야 합니다.

## 정리

- 뷰는 저장된 쿼리, 머티리얼라이즈드 뷰는 저장된 결과(REFRESH 필요).
- 자동 증가는 IDENTITY(ALWAYS), 번호 건너뜀은 정상.
- 스키마로 이름과 권한을 구분한다.
