# 09장 ∙ 집합 연산과 CTE - 재귀 쿼리까지

## 학습 목표

- UNION / UNION ALL / INTERSECT / EXCEPT 로 결과 집합을 합치고 비교할 수 있다.
- WITH(CTE)로 복잡한 쿼리를 단계별로 나누어 작성할 수 있다.
- 재귀 CTE 로 조직도·분류 트리 같은 계층 데이터를 조회할 수 있다.
- [심화] generate_series 와 데이터 변경 CTE 를 활용할 수 있다.

예제 파일: `examples/09_set_cte.sql`

## 집합 연산

| 연산 | 결과 | 중복 |
|---|---|---|
| `A UNION B` | 합집합 | 제거 |
| `A UNION ALL B` | 합집합 | 유지 (정렬·비교가 없어 빠름) |
| `A INTERSECT B` | 교집합 | 제거 |
| `A EXCEPT B` | 차집합 (A 에만 있는 것) | 제거 |

규칙: 두 쿼리의 **컬럼 수가 같고 대응하는 자료형이 호환**되어야 합니다. 결과 컬럼 이름은 첫 번째 쿼리를 따르고, `ORDER BY` 는 맨 마지막에 한 번만 씁니다.

## CTE (Common Table Expression)

```
WITH 이름1 AS (SELECT ...),
     이름2 AS (SELECT ... FROM 이름1 ...)
SELECT ... FROM 이름2 ...;
```

CTE 는 쿼리 안에서만 쓰는 **임시 이름 붙은 결과**입니다. 인라인 뷰와 같은 일을 하지만 위에서 아래로 읽을 수 있고, 같은 결과를 여러 번 참조할 수 있습니다.

## 재귀 CTE

```
WITH RECURSIVE 이름 AS (
    시작 쿼리                         -- ① 앵커: 처음 한 번
    UNION ALL
    SELECT ... FROM 테이블 JOIN 이름   -- ② 재귀: 직전 결과를 이용해 반복
    WHERE 종료 조건                    -- 새 행이 없으면 멈춤
)
SELECT ... FROM 이름;
```

동작 순서: ① 앵커가 `1` 을 만든다 → ② 직전 결과(1)로 `2` → ③ 직전 결과(2)로 `3` … → `n < 5` 가 거짓이 되어 새 행이 없으면 종료.

> [!WARN] 무한 루프
> 데이터에 순환(A의 상사가 B, B의 상사가 A)이 있으면 재귀 CTE 가 끝나지 않습니다. 깊이 제한(`WHERE depth < 10`)을 두거나 PostgreSQL 14+ 의 `CYCLE` 절을 사용합니다.

## 정리

- 집합 연산은 컬럼 수·타입이 같아야 하고, 기본은 UNION ALL.
- CTE 로 복잡한 쿼리를 단계별로 나눠 쓰고 검증한다.
- 계층 데이터는 재귀 CTE: 앵커 + UNION ALL + 재귀부.
