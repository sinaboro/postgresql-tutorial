## 데이터베이스와 DBMS

**데이터베이스(Database)** 는 여러 사람이 함께 쓰기 위해 체계적으로 모아 둔 데이터의 집합이고, 이를 저장·검색·수정·보호하는 소프트웨어가 **DBMS(Database Management System)** 입니다. PostgreSQL, MySQL, Oracle, SQL Server 가 대표적인 DBMS 입니다.

| 비교 | 엑셀 파일 | 데이터베이스(DBMS) |
|---|---|---|
| 동시 사용 | 한 사람이 열면 다른 사람은 읽기 전용 | 수천 명이 동시에 읽고 써도 일관성 유지 |
| 데이터 규칙 | 아무 값이나 입력 가능 | 자료형·제약 조건으로 잘못된 값 차단 |
| 데이터 양 | 약 100만 행 한계, 느려짐 | 수억 행도 인덱스로 빠르게 검색 |
| 장애 대응 | 파일이 깨지면 끝 | 트랜잭션·로그·백업으로 복구 |
| 권한 | 파일 단위 | 테이블·컬럼·행 단위 권한 |

**관계형 데이터베이스(RDB)** 는 데이터를 행(row)과 열(column)로 된 **테이블**에 저장하고, 테이블끼리는 **키(key)** 로 관계를 맺습니다. 테이블에 질문하는 표준 언어가 **SQL(Structured Query Language)** 입니다.

| SQL 분류 | 의미 | 주요 명령 | 교재 |
|---|---|---|---|
| DDL (Definition) | 구조 정의 | `CREATE`, `ALTER`, `DROP`, `TRUNCATE` | 2장 |
| DML (Manipulation) | 데이터 조작 | `INSERT`, `UPDATE`, `DELETE`, `MERGE` | 3장 |
| DQL (Query) | 데이터 조회 | `SELECT` | 4~10장 |
| DCL (Control) | 권한 제어 | `GRANT`, `REVOKE` | 17장 |
| TCL (Transaction) | 트랜잭션 제어 | `BEGIN`, `COMMIT`, `ROLLBACK` | 14장 |

## 왜 PostgreSQL 인가

- **완전한 오픈소스**(PostgreSQL License): 상용 서비스에도 무료로 쓸 수 있습니다.
- **표준 SQL 준수도가 높고 기능이 풍부**: 윈도우 함수, CTE, JSONB, 배열, 전문 검색, 사용자 정의 타입·함수, 확장(Extension).
- **신뢰성**: MVCC 기반 동시성 제어, 강력한 트랜잭션, 30년 넘게 검증된 엔진.
- **시장**: Stack Overflow 개발자 설문에서 수년째 가장 많이 쓰고 선호하는 데이터베이스로 꼽히며, AWS RDS/Aurora, Google Cloud SQL, Azure, Supabase 등 대부분의 클라우드가 기본 제공합니다.
- **버전 정책**: 매년 가을 메이저 버전 출시, 각 버전 5년 지원. 이 교재은 **PostgreSQL 18** 기준이며 17 이상이면 모든 예제가 동작합니다(13장 skip scan 설명만 18 전용).


## 실습 서버 준비 - Docker 로 PostgreSQL 실행

PostgreSQL 을 PC 에 직접 설치하지 않고 **Docker 컨테이너**로 실행합니다. 모든 사람이 같은 버전·같은 설정·같은 데이터로 실습할 수 있고, 망가져도 명령 한 줄로 처음 상태로 되돌릴 수 있습니다.

| 용어 | 의미 |
|---|---|
| 이미지(image) | 프로그램 설치가 끝난 상태를 찍어 둔 틀 (`postgres:18`) |
| 컨테이너(container) | 이미지로 실행한 프로그램 하나 (`pg-shop`) |
| 볼륨(volume) | 컨테이너를 지워도 남는 데이터 저장소 (`pgdata`) |
| docker compose | `docker-compose.yml` 에 적은 설정대로 컨테이너를 실행하는 명령 |

### 1단계 - Docker Desktop 설치

1. https://www.docker.com/products/docker-desktop/ 에서 **Docker Desktop** 을 받아 설치합니다. (Windows 는 설치 중 WSL 2 사용을 권장하는 기본값 그대로)
2. 설치 후 재부팅하고 Docker Desktop 을 실행합니다. 화면 왼쪽 아래가 **Engine running** 이면 준비된 것입니다.
3. 명령 프롬프트(또는 PowerShell, 터미널)에서 확인합니다.

```
docker --version
docker compose version
```

### 2단계 - 저장소 받기와 서버 시작

```
git clone https://github.com/sinaboro/postgresql-tutorial.git
cd postgresql-tutorial
docker compose up -d
docker compose ps
```

git 이 없으면 GitHub 페이지의 **Code → Download ZIP** 으로 받아 압축을 풀고, 그 폴더에서 `docker compose up -d` 를 실행합니다. 처음에는 `postgres:18` 이미지를 내려받느라 1~2분 걸립니다. `docker compose ps` 의 STATUS 가 **healthy** 가 되면 준비 완료입니다.

처음 시작할 때 `setup/01_schema.sql`, `setup/02_seed.sql` 이 자동으로 실행되어 **shop 데이터베이스와 샘플 데이터가 이미 만들어져 있습니다.**

| 항목 | 값 |
|---|---|
| 호스트 / 포트 | `localhost` / `5432` |
| 데이터베이스 | `shop` |
| 사용자 / 비밀번호 | `postgres` / `postgres` |

### 자주 쓰는 Docker 명령

| 명령 | 하는 일 |
|---|---|
| `docker compose up -d` | 서버 시작 (처음이면 생성 + 샘플 데이터 입력) |
| `docker compose stop` | 서버 중지 (데이터는 유지) |
| `docker compose ps` | 상태 확인 |
| `docker compose logs -f` | 서버 로그 보기 (오류 원인 확인, Ctrl+C 로 빠져나옴) |
| `docker exec -it pg-shop psql -U postgres -d shop` | 컨테이너 안의 psql 로 접속 (`\q` 로 종료) |
| `docker compose down -v` | 컨테이너와 데이터 볼륨 삭제 → 다음 `up` 때 shop 을 처음 상태로 다시 생성 |

> [!WARN] 자주 생기는 문제
> - **`docker` 명령을 찾을 수 없음 / 연결 오류**: Docker Desktop 이 실행 중인지 확인합니다. 작업 표시줄의 고래 아이콘이 초록색(running)이어야 합니다.
> - **5432 포트 사용 중(port is already allocated)**: PC 에 PostgreSQL 이 따로 설치되어 있는 경우입니다. `docker-compose.yml` 의 `"5432:5432"` 를 `"5433:5432"` 로 바꾸고 다시 `docker compose up -d` 한 뒤, DBeaver 에서 포트를 5433 으로 씁니다.
> - **샘플 데이터가 없음**: 샘플 데이터는 볼륨이 **처음 만들어질 때만** 들어갑니다. `docker compose down -v` 후 `docker compose up -d` 로 다시 만듭니다.
> - **회사·학교 PC 에서 WSL 2 / 가상화 오류**: BIOS 의 가상화(VT-x / AMD-V) 설정과 Windows 기능의 “Linux용 Windows 하위 시스템”이 켜져 있어야 합니다.

## 접속 도구 - 수업은 DBeaver 로 진행

| 도구 | 특징 | 이 과정에서 |
|---|---|---|
| **DBeaver** (Community, 무료) | 여러 DBMS 를 지원하는 범용 GUI. 자동완성, 결과 그리드, ER 다이어그램, 데이터 가져오기/내보내기 | **수업 표준 도구**. 모든 실습을 DBeaver 로 진행 |
| **psql** | PostgreSQL 공식 명령줄 도구 (Docker 컨테이너 안에 포함) | 18장 `\copy`·백업 명령 |
| pgAdmin 4 | 공식 웹 GUI | 이 과정에서는 사용하지 않음 |

### DBeaver 설치

1. https://dbeaver.io/download/ → **DBeaver Community** 의 Windows (installer) 를 받아 설치합니다. (macOS 는 dmg, Linux 는 deb/rpm)
2. 첫 실행 시 “샘플 데이터베이스를 만들까요?” 질문은 **아니요**, 통계 전송 동의는 원하는 대로 선택합니다.
3. 메뉴가 영어라면 그대로 쓰는 것을 권장합니다(검색·질문할 때 영어 메뉴 이름이 편함). 교재도 영어 메뉴 이름으로 적습니다.

### PostgreSQL 연결 만들기

1. 왼쪽 위 **New Database Connection**(플러그 + 아이콘) 또는 메뉴 `Database → New Database Connection` → **PostgreSQL** 선택 → Next
2. Main 탭 입력

| 항목 | 값 |
|---|---|
| Connect by | Host |
| Host / Port | `localhost` / `5432` |
| Database | `shop` |
| Authentication | Database Native |
| Username / Password | `postgres` / `postgres`, **Save password** 체크 |

3. PostgreSQL 탭에서 **Show all databases** 를 체크하면 왼쪽 트리에 모든 DB 가 보입니다.
4. **Test Connection** → 처음이면 “Download driver files” 창이 뜨고 **Download** 를 누르면 JDBC 드라이버를 받습니다. `Connected` 가 나오면 Finish.

> [!NOTE] 드라이버 다운로드
> DBeaver 는 첫 연결 때 PostgreSQL JDBC 드라이버를 인터넷에서 내려받습니다. 다운로드 창이 뜨지 않거나 실패하면 인터넷 연결을 확인하고, `Database → Driver Manager → PostgreSQL → Download/Update` 로 다시 받습니다.

### SQL 편집기 사용법

연결을 선택하고 `Ctrl+]` (또는 메뉴 `SQL Editor → New SQL script`) 로 편집기를 엽니다. 저장소의 예제 파일은 `File → Open File...` 로 열고, 편집기 위쪽의 **활성 연결/데이터베이스 선택 상자**에서 `shop` 을 고릅니다.

| 단축키 | 동작 | 언제 |
|---|---|---|
| `Ctrl+Enter` | 커서가 있는 **문장 하나** 실행 (선택했으면 선택 영역을 한 문장으로 실행) | 쿼리 하나씩 실행 |
| `Alt+X` | **스크립트 실행** - 여러 문장을 차례로 실행, 결과는 탭마다 | 예제 블록 전체, setup 파일 |
| `Ctrl+Space` | 자동완성 (테이블·컬럼 이름) | 항상 |
| `Ctrl+Shift+F` | SQL 정렬(포맷) | 긴 쿼리 정리 |
| `Ctrl+/` | 줄 주석 켜기/끄기 | |
| `Ctrl+Shift+E` | 실행 계획(EXPLAIN) 보기 | 13장 |
| `Ctrl+Shift+O` | 서버 출력(NOTICE) 창 켜기/끄기 | 15장 `RAISE NOTICE` |

> [!POINT] 예제 파일 실행 요령
> - 예제 파일은 `-- @ex 04-01 제목` 주석으로 예제가 나뉩니다. **예제 블록 전체를 마우스로 선택 → `Alt+X`** 가 가장 확실합니다. 선택하지 않고 `Alt+X` 를 누르면 파일 전체가 실행되니 주의하세요.
> - DBeaver 는 기본 설정에서 **빈 줄을 문장 구분으로 볼 수 있어**, 빈 줄이 들어간 긴 문장에 `Ctrl+Enter` 를 쓰면 일부만 실행됩니다. 문장은 `;` 로 확실히 끝내고, 헷갈리면 선택 후 실행하세요. (설정: `Window → Preferences → Editors → SQL Editor → SQL Processing → Blank line is statement delimiter`)
> - 결과는 아래 **결과 그리드**에 표로 나옵니다. INSERT/UPDATE 결과(`UPDATE 1`)는 **Statistics** 탭의 Updated Rows 로 확인합니다. 교재의 ‘실행 결과’는 psql 형식이라 모양만 다를 뿐 내용은 같습니다.
> - 오류가 나면 아래쪽에 빨간 메시지가 뜹니다. 트랜잭션 모드(14장)에서 오류가 났다면 Rollback 을 눌러야 다음 실행이 됩니다.

### psql 메타 명령과 DBeaver 대응표

`\` 로 시작하는 psql 메타 명령은 SQL 이 아니어서 **DBeaver 에서는 실행되지 않습니다**. 그래서 이 저장소의 예제는 메타 명령 대신 같은 정보를 SQL(`information_schema`)로 조회하도록 작성했습니다(예: 01-03, 01-04). 18장의 `\copy` 만 psql 전용입니다.

| psql | 의미 | DBeaver 에서는 |
|---|---|---|
| `\l` / `\c shop` | DB 목록 / DB 전환 | 왼쪽 Database Navigator, 편집기 위 데이터베이스 선택 상자 |
| `\dt` / `\dv` | 테이블 / 뷰 목록 | Navigator 의 `shop → Schemas → public → Tables / Views` |
| `\d 테이블` | 테이블 구조 | 테이블 더블클릭 → **Properties**(Columns, Constraints, Indexes) / **DDL** 탭 |
| `\df` | 함수 목록 | Navigator 의 `Functions` (Procedures 포함) |
| `\du` | 롤 목록 | Navigator 의 연결 아래 `Roles` |
| `\i 파일` | 파일 실행 | 파일 열기 → `Alt+X` |
| `\timing` | 실행 시간 | 결과 그리드 아래 상태 표시줄에 자동 표시 |
| `\x` | 세로 출력 | 결과 그리드에서 `Tab` 키 (Record 보기 전환) |
| `\copy` | CSV 입출력 | 테이블 우클릭 → Export Data / Import Data (18장) |

## 실습 데이터베이스 확인과 초기화

Docker 로 서버를 시작하면 shop DB 가 이미 준비되어 있습니다. DBeaver 에서 연결한 뒤 새 편집기에 다음을 실행해 **120** 이 나오면 준비 완료입니다.

```
SELECT count(*) FROM orders;
```

> [!TIP] 실습 데이터 초기화 - 두 가지 방법
> 3장처럼 데이터를 바꾸는 실습 뒤에는 처음 상태로 되돌린 다음 다음 장으로 넘어가세요.
> - **DBeaver 에서 (빠름)**: `setup/01_schema.sql` 을 열고 `Alt+X`, 이어서 `setup/02_seed.sql` 을 열고 `Alt+X`. 테이블을 지우고 다시 만듭니다.
> - **Docker 로 (완전 초기화)**: `docker compose down -v` → `docker compose up -d`. 17장에서 만든 사용자(ROLE)까지 모두 지워집니다. 이때 DBeaver 연결은 한 번 끊었다가(Disconnect) 다시 연결합니다.

> [!QA] 자주 묻는 질문
> - **Q. 세미콜론(;)을 꼭 붙여야 하나요?** psql 은 `;` 를 만나야 실행합니다. 붙이지 않으면 프롬프트가 `shop-#` 으로 바뀌며 다음 줄 입력을 기다립니다. GUI 에서는 한 문장만 실행할 때 생략해도 되지만 습관적으로 붙이세요.
> - **Q. 데이터베이스와 스키마는 뭐가 다른가요?** DB 는 독립된 저장소(다른 DB 의 테이블을 바로 조인할 수 없음), 스키마는 DB 안의 폴더입니다. 12장에서 다룹니다.
> - **Q. 대문자로 만든 테이블 이름은?** `CREATE TABLE "Users"` 처럼 큰따옴표로 만들면 그 뒤로도 항상 `"Users"` 로 써야 합니다. 이름은 소문자 + 밑줄(snake_case)로 짓는 것이 PostgreSQL 관례입니다.

## 정리

- DBMS 는 데이터를 안전하게, 동시에, 빠르게 다루기 위한 소프트웨어이며 SQL 로 대화한다.
- 실습은 DBeaver 로: 블록 선택 후 `Alt+X`, 한 문장은 `Ctrl+Enter`.
- psql 메타 명령(`\dt`, `\d`)은 SQL 이 아니라 psql 의 기능이라 DBeaver 에서는 동작하지 않는다.
- 실습 DB 는 `setup/` 의 파일 3개로 언제든 초기 상태로 되돌릴 수 있다.
