# 15장 ∙ 함수, 프로시저, 트리거 - PL/pgSQL

## 학습 목표

- SQL 함수와 PL/pgSQL 함수를 만들고 호출할 수 있다.
- 변수, IF, LOOP, 예외 처리(EXCEPTION), RAISE 를 사용할 수 있다.
- 함수와 프로시저(CALL)의 차이를 설명할 수 있다.
- BEFORE / AFTER 트리거로 데이터 보정과 변경 이력을 자동화할 수 있다.

예제 파일: `examples/15_plpgsql.sql`

## 함수의 기본 구조

```
CREATE OR REPLACE FUNCTION 함수명(매개변수 타입, ...)
RETURNS 반환타입
LANGUAGE plpgsql            -- 또는 sql
AS $$
DECLARE
    변수 타입;
BEGIN
    ...
    RETURN 값;
END;
$$;
```

`$$ ... $$` 는 **달러 인용(dollar quoting)** 으로, 함수 본문 안에서 작은따옴표를 이스케이프하지 않고 쓸 수 있게 해 줍니다.

| 구분 | `LANGUAGE sql` | `LANGUAGE plpgsql` |
|---|---|---|
| 내용 | SQL 문 하나(또는 여러 개) | 변수, IF, LOOP, 예외 처리 가능 |
| 장점 | 간단, 인라인 최적화 가능 | 절차적 로직 |
| 예 | 부가세 계산, 리포트 조회 | 주문 처리, 등급 계산 |

함수 변동성(volatility) 표시: `IMMUTABLE`(같은 입력 → 항상 같은 결과, 예: 계산), `STABLE`(한 쿼리 안에서는 같은 결과, 예: 조회), `VOLATILE`(기본값, 데이터 변경·난수).

> [!TIP] DBeaver 에서 함수 만들고 NOTICE 보기
> - `CREATE FUNCTION ... $$ ... $$;` 처럼 긴 문장은 **전체를 선택한 뒤 실행**합니다. 예제 파일의 함수 본문에는 빈 줄을 넣지 않아 `Ctrl+Enter` 로도 한 문장으로 인식되지만, 직접 작성할 때 본문에 빈 줄을 넣으면 DBeaver 가 문장을 잘라 `unterminated dollar-quoted string` 오류가 납니다.
> - `RAISE NOTICE` 메시지는 결과 그리드가 아니라 **서버 출력(Output) 창**에 나옵니다. `Ctrl+Shift+O` 로 창을 열어 두세요.
> - 만든 함수·트리거는 Navigator 의 `Functions`, 테이블의 `Triggers` 에서 확인하고 소스를 편집할 수 있습니다.

## 프로시저

| 구분 | FUNCTION | PROCEDURE (11+) |
|---|---|---|
| 호출 | `SELECT f()` (쿼리 안에서 사용 가능) | `CALL p()` |
| 반환값 | 있음 | 없음 (OUT 매개변수는 가능) |
| 트랜잭션 제어 | 불가 | 내부에서 `COMMIT` / `ROLLBACK` 가능 |
| 용도 | 계산, 조회, 단일 업무 처리 | 배치 작업 (대량 데이터를 나눠 커밋) |

## 트리거

트리거는 테이블에 INSERT / UPDATE / DELETE 가 일어날 때 **자동으로 실행되는 함수**입니다.

| 구분 | 설명 |
|---|---|
| `BEFORE` | 변경 전에 실행. `NEW` 를 고쳐서 저장될 값을 바꾸거나, `RETURN NULL` 로 변경을 취소 |
| `AFTER` | 변경 후 실행. 이력 기록, 다른 테이블 갱신 |
| `FOR EACH ROW` / `STATEMENT` | 행마다 / 문장마다 한 번 |
| `OLD` / `NEW` | 변경 전 행 / 변경 후 행 (DELETE 는 OLD 만, INSERT 는 NEW 만) |
| `WHEN (조건)` | 조건이 참일 때만 실행 |

> [!WARN] 트리거는 보이지 않는 로직
> 트리거는 편리하지만 SQL 만 봐서는 실행되는지 알 수 없어 디버깅이 어렵습니다. 감사 로그, `updated_at` 자동 갱신, 데이터 정규화처럼 **“항상 반드시”** 일어나야 하는 일에만 쓰고, 업무 로직 대부분은 애플리케이션이나 명시적 함수 호출에 두도록 권장합니다. 트리거 안에서 같은 테이블을 다시 수정하면 무한 반복될 수 있으니 주의합니다.

> [!QA] 자주 묻는 질문
> - **Q. 함수를 수정하려면?** `CREATE OR REPLACE FUNCTION` 으로 다시 만듭니다. 매개변수나 반환 타입을 바꾸려면 `DROP FUNCTION 이름(타입들)` 후 다시 만듭니다.
> - **Q. PL/pgSQL 디버깅은?** `RAISE NOTICE '값: %', 변수;` 로 중간값을 찍는 것이 가장 간단합니다. DBeaver 에서는 Output 창(`Ctrl+Shift+O`)에서 확인합니다.

## 정리

- 단순 계산·조회는 SQL 함수, 절차적 로직은 PL/pgSQL.
- 함수 안의 오류는 호출한 트랜잭션 전체를 취소한다. 트랜잭션 제어가 필요하면 프로시저.
- 트리거는 BEFORE(값 보정), AFTER(이력 기록). 꼭 필요한 곳에만.
