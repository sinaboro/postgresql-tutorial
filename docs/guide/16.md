## JSON 과 JSONB

| 구분 | `JSON` | `JSONB` |
|---|---|---|
| 저장 형태 | 입력한 텍스트 그대로 | 분해한 이진 형태 (키 순서·공백·중복 키 정리) |
| 조회 속도 | 매번 파싱 → 느림 | 빠름 |
| 인덱스 | 불가 | GIN 인덱스 가능 |
| 권장 | 입력 원문을 그대로 보관해야 할 때만 | **거의 항상 JSONB** |

상품마다 속성이 다른 경우(노트북은 RAM, 옷은 사이즈) 컬럼을 계속 늘리는 대신 `attrs JSONB` 에 담으면 유연합니다. 단, 모든 상품에 공통이고 자주 검색·조인하는 값(가격, 분류)은 일반 컬럼으로 둡니다.

| 연산자 | 의미 | 예 |
|---|---|---|
| `->` | 키/인덱스로 꺼내기 (결과 JSONB) | `attrs -> 'sizes'` |
| `->>` | 꺼내서 **텍스트**로 | `attrs ->> 'brand'` |
| `#>` / `#>>` | 경로로 꺼내기 | `attrs #>> '{sizes,1}'` |
| `@>` | 포함하는가 (GIN 인덱스 사용) | `attrs @> '{"brand":"한빛"}'` |
| `?` | 키가 있는가 | `attrs ? 'sizes'` |
| `\|\|` / `-` | 합치기(추가·덮어쓰기) / 키 삭제 | `attrs \|\| '{"a":1}'` |

> [!WARN] 배열·JSONB 남용 주의
> 태그처럼 단순 목록은 배열이 편하지만, 원소마다 추가 정보가 붙거나(태그 생성일), 다른 테이블과 조인해야 하거나, 원소 단위로 FK 무결성이 필요하면 **별도 테이블로 정규화**하는 것이 맞습니다(11장 1NF). 배열 인덱스는 1부터 시작한다는 점도 다른 언어와 다릅니다.

## 전문 검색 (Full Text Search)

LIKE 는 단어 경계, 어형 변화, 관련도 순위를 모릅니다. 전문 검색은 문서를 단어(lexeme) 목록인 `tsvector` 로, 검색어를 `tsquery` 로 바꿔 `@@` 연산자로 비교합니다.

> [!NOTE] 한국어 전문 검색
> PostgreSQL 기본 설치에는 한국어 형태소 분석 사전이 없어, `simple` 설정은 띄어쓰기 단위로만 나눕니다('배송이' 와 '배송' 은 다른 단어). 16-12 의 영어 설정은 어간 추출(indexes, indexing → index)을 합니다. 한국어 검색 품질이 중요하면 **pg_trgm(아래)**, 외부 형태소 분석기 확장(textsearch_ko, pg_bigm 등), 또는 Elasticsearch/OpenSearch 같은 검색 엔진을 함께 씁니다.

## [확장] pg_trgm - 부분 문자열 검색

pg_trgm 은 문자열을 3글자 조각(trigram)으로 나눠 유사도를 계산하고, `LIKE '%단어%'` 검색에도 GIN 인덱스를 쓸 수 있게 해 줍니다. PostgreSQL 설치에 포함된 확장이라 `CREATE EXTENSION` 만 하면 됩니다.
