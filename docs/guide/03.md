# 03장 ∙ 데이터 다루기 - INSERT / UPDATE / DELETE

## 학습 목표

- INSERT 로 한 행·여러 행·조회 결과를 넣을 수 있다.
- UPDATE / DELETE 를 WHERE 조건과 함께 안전하게 사용할 수 있다.
- RETURNING 으로 변경된 행을 바로 확인할 수 있다.
- UPSERT(`ON CONFLICT`)와 `MERGE` 로 “있으면 수정, 없으면 입력”을 처리할 수 있다.

예제 파일: `examples/03_dml.sql` (실습 후 `setup/` 스크립트로 데이터 초기화)

## INSERT

```
INSERT INTO 테이블 (컬럼1, 컬럼2, ...) VALUES (값1, 값2, ...);
INSERT INTO 테이블 (컬럼1, 컬럼2) VALUES (...), (...), (...);    -- 여러 행
INSERT INTO 테이블 (컬럼1, 컬럼2) SELECT ... ;                    -- 조회 결과
```

> [!POINT] INSERT 에는 항상 컬럼 목록을
> `INSERT INTO todo VALUES (...)` 처럼 컬럼 목록을 생략하면 테이블의 컬럼 순서에 의존하게 됩니다. 나중에 컬럼이 추가되면 모든 INSERT 가 깨지므로 **항상 컬럼 목록을 쓰는 습관**을 들이세요. psql 이 출력하는 `INSERT 0 3` 의 0 은 과거 호환용 값(OID), 3 은 들어간 행 수입니다.

RETURNING 은 PostgreSQL 의 강력한 기능입니다. 자동 생성된 ID 를 다시 조회할 필요 없이 바로 받아 볼 수 있어 애플리케이션 개발 시 매우 자주 씁니다.

## UPDATE 와 DELETE

```
UPDATE 테이블 SET 컬럼 = 값 [, 컬럼 = 값 ...] WHERE 조건;
DELETE FROM 테이블 WHERE 조건;
```

@@ex 03-05 03-06

> [!WARN] WHERE 없는 UPDATE / DELETE
> 실무 사고 1순위입니다. 예제 03-07 처럼 **먼저 `BEGIN` 으로 트랜잭션을 열고** 실행 → 결과 확인 → `COMMIT` 또는 `ROLLBACK` 하는 습관을 들이세요. 또 UPDATE/DELETE 를 실행하기 전에 같은 WHERE 로 `SELECT` 를 먼저 실행해 대상 행을 확인하는 것도 좋은 습관입니다.

@@ex 03-07

> [!NOTE] 행의 순서
> 03-07 에서 UPDATE 한 뒤 ORDER BY 없이 조회하면 행 순서가 바뀌어 보일 수 있습니다. PostgreSQL 은 UPDATE 시 행의 새 버전을 다른 위치에 쓰기 때문입니다(14장 MVCC). **순서가 필요하면 반드시 ORDER BY** 를 쓴다는 점을 강조합니다.

## UPSERT 와 MERGE

“이미 있으면 수정, 없으면 입력”은 장바구니 담기, 재고 동기화, 일별 집계 테이블 갱신 등에 흔히 필요합니다.

| 방법 | 특징 |
|---|---|
| `INSERT ... ON CONFLICT (키) DO UPDATE` | PostgreSQL 전용, 동시 실행에도 안전(원자적), 가장 많이 씀 |
| `INSERT ... ON CONFLICT DO NOTHING` | 중복이면 조용히 건너뜀 |
| `MERGE` (15+) | SQL 표준, 원본 테이블과 비교해 INSERT/UPDATE/DELETE 를 한 번에 |

`EXCLUDED` 는 “넣으려다 충돌한 새 행”을 가리키는 특별한 이름입니다.

> [!QA] 자주 묻는 질문
> - **Q. DELETE 한 데이터를 되살릴 수 있나요?** COMMIT 했다면 SQL 로는 되돌릴 수 없습니다. 백업(18장)에서 복구해야 합니다. 그래서 실무에서는 실제 삭제 대신 `deleted_at` 컬럼을 두는 **소프트 삭제**를 많이 씁니다.
> - **Q. 대량 입력은 INSERT 를 반복하면 되나요?** 수만 행 이상이면 `COPY` (18장)나 여러 행 INSERT 를 쓰면 수십 배 빠릅니다.

## 정리

- INSERT 는 컬럼 목록을 명시하고, RETURNING 으로 결과를 바로 받는다.
- UPDATE/DELETE 는 WHERE 를 먼저 SELECT 로 검증하고, 트랜잭션 안에서 실행한다.
- 있으면 수정·없으면 입력은 `ON CONFLICT` 또는 `MERGE`.
