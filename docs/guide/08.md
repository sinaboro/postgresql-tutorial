# 08장 ∙ 서브쿼리 - 쿼리 안의 쿼리

## 학습 목표

- 스칼라·다중 행·상관 서브쿼리를 구분하고 알맞은 위치(SELECT/FROM/WHERE)에 쓸 수 있다.
- IN, EXISTS, ANY, ALL 을 사용하고 NOT IN 의 NULL 함정을 피할 수 있다.
- 서브쿼리로 UPDATE / DELETE 대상을 정할 수 있다.
- [심화] LATERAL 로 그룹별 TOP-N 을 구할 수 있다.

예제 파일: `examples/08_subquery.sql`

## 서브쿼리의 종류

| 종류 | 반환 | 위치 | 예 |
|---|---|---|---|
| 스칼라 서브쿼리 | 1행 1열 (값 하나) | SELECT, WHERE 의 비교 | `price > (SELECT avg(price) ...)` |
| 다중 행 서브쿼리 | 여러 행 1열 | `IN`, `ANY`, `ALL` | `id IN (SELECT ...)` |
| 상관 서브쿼리 | 바깥 행마다 다시 실행 | WHERE, SELECT, EXISTS | `WHERE x > (SELECT ... WHERE 안.k = 밖.k)` |
| 인라인 뷰 | 테이블 | FROM (별칭 필수) | `FROM (SELECT ...) t` |

## NOT IN 과 NULL

@@ex 08-04

`emp_id NOT IN (6, 7, NULL, ...)` 은 `emp_id <> 6 AND emp_id <> 7 AND emp_id <> NULL ...` 로 풀리는데, `<> NULL` 이 NULL 이므로 전체가 절대 참이 될 수 없습니다. orders.emp_id 에는 온라인 주문의 NULL 이 있어 결과가 0건이 되었습니다.

> [!WARN] NOT IN 대신 NOT EXISTS
> 서브쿼리 결과에 NULL 이 하나라도 섞일 수 있다면 `NOT IN` 은 조용히 0건을 돌려줍니다. **“없는 것 찾기”는 `NOT EXISTS` 나 `LEFT JOIN ... IS NULL`** 로 쓰도록 강하게 권합니다. 실무 버그 사례로 자주 나옵니다.

## EXISTS 와 상관 서브쿼리

`EXISTS (서브쿼리)` 는 서브쿼리가 한 행이라도 돌려주면 참입니다. 무엇을 SELECT 하는지는 상관없어 관례적으로 `SELECT 1` 을 씁니다.

@@ex 08-05 08-06

08-06 의 서브쿼리는 바깥 행(`p`)의 `category_id` 를 참조하므로 상품마다 다시 계산됩니다. 이것이 **상관 서브쿼리**입니다. 같은 결과를 10장의 윈도우 함수 `avg(price) OVER (PARTITION BY category_id)` 로도 구할 수 있습니다.

## 인라인 뷰와 ANY / ALL

@@ex 08-07 08-08

| 표현 | 의미 |
|---|---|
| `x > ALL (서브쿼리)` | 모든 값보다 크다 (= 최댓값보다 크다) |
| `x > ANY (서브쿼리)` | 하나라도보다 크다 (= 최솟값보다 크다) |
| `x = ANY (서브쿼리 또는 배열)` | `IN` 과 같다 |

## [심화] LATERAL

일반 FROM 절 서브쿼리는 앞의 테이블을 참조할 수 없지만, `LATERAL` 을 붙이면 **앞 테이블의 각 행마다** 서브쿼리를 실행할 수 있습니다. “분류별 상위 2개”, “고객별 최근 주문 3건” 같은 그룹별 TOP-N 에 유용합니다(10장 윈도우 함수 방식과 비교).

## 정리

- 서브쿼리는 안쪽부터 읽는다. 스칼라 서브쿼리는 반드시 한 행.
- “없는 것 찾기”는 NOT IN 이 아닌 NOT EXISTS.
- 그룹별 TOP-N 은 LATERAL 또는 윈도우 함수(10장).
