|---|---|
| **psycopg 3** (`psycopg`) | 현재 권장 PostgreSQL 드라이버. `psycopg[binary]` 로 설치하면 별도 빌드 불필요 |

## INSERT 와 트랜잭션

psycopg 는 첫 쿼리 때 자동으로 트랜잭션을 시작하므로 **`commit()` 을 호출해야 반영**됩니다. `with connect() as conn:` 블록은 정상 종료 시 commit, 예외 시 rollback 합니다. `with conn.transaction():` 블록은 그 안의 작업만 하나의 트랜잭션(또는 SAVEPOINT)으로 묶습니다.

@@py python/03_transaction.py

> [!TEACH] 자주 하는 실수
> - INSERT 후 `commit()` 을 빼먹어 “DB 에 데이터가 안 들어가요” → 다른 도구에서 조회하면 보이지 않음.
> - 예외를 잡고 계속 쿼리를 실행 → 14장의 `current transaction is aborted` 오류. `rollback()` 을 먼저 해야 함.
> - 반복문 안에서 매번 connect → 접속 비용이 큼. 연결은 재사용하고, 웹 서비스는 커넥션 풀(`psycopg_pool`)을 사용.

> [!NOTE] 데드락에서 누가 취소되나
> ⑤ 에서는 B 가 먼저 A 를 기다리기 시작했으므로, 나중에 교착을 완성한 A 쪽 대기에서 감지될 수도 있고 B 쪽이 취소될 수도 있습니다(실행 타이밍에 따라 다름). 중요한 것은 **한쪽이 취소되고 다른 쪽은 진행된다**는 점과, 취소된 쪽은 재시도해야 한다는 점입니다.

> [!QA] 예상 질문
> - **Q. ORM(SQLAlchemy, Django ORM)을 쓰면 SQL 을 몰라도 되나요?** ORM 이 만드는 SQL 을 이해하지 못하면 N+1 쿼리, 불필요한 조인 같은 성능 문제를 해결할 수 없습니다. ORM 을 쓰더라도 이 과정의 SQL 지식이 기반이 됩니다.

## 정리

- 접속 정보는 환경변수로, 값은 `%s` 파라미터로.
- psycopg 는 commit 해야 반영. 예외 후에는 rollback.
- 집계는 SQL, 분석·시각화는 pandas.
