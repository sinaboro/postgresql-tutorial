# 04장 ∙ SELECT 기초 - 원하는 행과 열 골라내기

## 학습 목표

- SELECT 로 필요한 컬럼과 계산식을 조회하고 별칭(AS)을 붙일 수 있다.
- WHERE 에서 비교·논리 연산자, IN, BETWEEN, LIKE, IS NULL 을 사용할 수 있다.
- ORDER BY, LIMIT / OFFSET, FETCH FIRST 로 정렬과 페이지 나누기를 할 수 있다.
- SQL 의 논리적 실행 순서를 설명할 수 있다.

예제 파일: `examples/04_select_basic.sql`

## SELECT 의 기본 구조

```
SELECT   컬럼, 식 AS 별칭        -- ⑤ 무엇을 보여 줄까
FROM     테이블                  -- ① 어디에서
WHERE    행 조건                 -- ② 어떤 행을
GROUP BY 그룹 기준               -- ③ (6장)
HAVING   그룹 조건               -- ④ (6장)
ORDER BY 정렬 기준               -- ⑥ 어떤 순서로
LIMIT    개수 OFFSET 건너뛸 수;   -- ⑦ 몇 개만
```

작성 순서와 **실행 순서(①~⑦)** 가 다르다는 점이 이 장의 핵심입니다.

## WHERE - 행 거르기

| 연산자 | 의미 | 예 |
|---|---|---|
| `=`, `<>` (`!=`) | 같다, 다르다 | `grade <> 'BRONZE'` |
| `>`, `>=`, `<`, `<=` | 크기 비교 | `price >= 1000000` |
| `AND`, `OR`, `NOT` | 논리 연산 (우선순위 NOT > AND > OR) | `a AND (b OR c)` |
| `IN (목록)` | 목록 중 하나 | `city IN ('대구', '대전')` |
| `BETWEEN a AND b` | a 이상 b 이하 (양끝 포함) | `price BETWEEN 30000 AND 60000` |
| `LIKE` / `ILIKE` | 패턴 (`%` 0자 이상, `_` 1자) / 대소문자 무시 | `name LIKE '%노트북%'` |
| `IS NULL` / `IS NOT NULL` | NULL 여부 | `phone IS NULL` |

## NULL - 값이 “없음”

NULL 은 0 도 빈 문자열도 아닌 **“알 수 없음”** 입니다. NULL 과의 비교·연산 결과는 참도 거짓도 아닌 NULL(unknown)이 되고, WHERE 는 참인 행만 통과시키므로 `= NULL` 은 항상 0건입니다.

@@ex 04-08 04-09

| A | B | A AND B | A OR B |
|---|---|---|---|
| TRUE | NULL | NULL | TRUE |
| FALSE | NULL | FALSE | NULL |
| NULL | NULL | NULL | NULL |

> [!TIP] IS DISTINCT FROM
> “NULL 도 하나의 값처럼 비교하고 싶을 때” `a IS DISTINCT FROM b` (다른가), `a IS NOT DISTINCT FROM b` (같은가)를 씁니다. 15장 트리거 예제에서 “가격이 실제로 바뀌었을 때만”을 판단할 때 사용합니다.

## 정렬과 개수 제한

@@ex 04-10 04-11

- `ORDER BY` 는 기본 오름차순(`ASC`), `DESC` 는 내림차순. 여러 기준은 쉼표로 나열합니다.
- PostgreSQL 은 NULL 을 **가장 큰 값**으로 취급해 오름차순이면 맨 뒤, 내림차순이면 맨 앞에 둡니다. `NULLS FIRST/LAST` 로 바꿉니다.
- 한글 정렬 순서는 데이터베이스 생성 시의 로케일(Collation)을 따릅니다.

@@ex 04-12 04-13

> [!NOTE] OFFSET 페이지네이션의 한계
> `OFFSET 100000` 은 앞의 10만 행을 읽고 버리므로 뒤 페이지일수록 느려집니다. 실무에서는 “마지막으로 본 id 보다 큰 것” `WHERE id > :last_id ORDER BY id LIMIT 20` 방식(키셋 페이지네이션)을 씁니다. 13장 인덱스와 연결해 설명할 수 있습니다.

## 날짜 조건과 실행 순서

@@ex 04-14

> [!TIP] 날짜 범위는 반열림 구간으로
> `order_date BETWEEN '2026-01-01' AND '2026-03-31'` 은 3월 31일 0시까지만 포함해 31일 낮 주문이 빠집니다. TIMESTAMP 컬럼은 **`>= 시작 AND < 다음날`** 형태로 쓰는 것이 안전합니다.

> [!QA] 자주 묻는 질문
> - **Q. `SELECT *` 를 써도 되나요?** 학습·탐색용으로는 편하지만, 프로그램 코드에서는 필요한 컬럼만 적어야 합니다(불필요한 데이터 전송, 컬럼 추가 시 영향).
> - **Q. ORDER BY 없이 조회하면 입력 순서대로 나오나요?** 보장되지 않습니다. 지금은 그렇게 보여도 수정·VACUUM·병렬 처리 후 바뀔 수 있습니다.
> - **Q. LIKE 에서 % 자체를 찾으려면?** `LIKE '%10\%%'` 처럼 역슬래시로 이스케이프합니다.

## 정리

- 실행 순서: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT.
- NULL 비교는 `IS NULL`, AND/OR 혼용 시 괄호 필수.
- 순서가 필요하면 ORDER BY, 날짜 범위는 `>= AND <`.
