# 18장 ∙ 운영 기초 - 모니터링, VACUUM, 백업과 복구

## 학습 목표

- 데이터베이스·테이블 크기, 접속 세션, 서버 설정을 조회할 수 있다.

## 서버 설정

설정은 `postgresql.conf`(데이터 디렉터리) 또는 `ALTER SYSTEM` 으로 바꾸고, 범위에 따라 세션·DB·롤 단위로도 덮어쓸 수 있습니다. `pg_settings.context` 가 `postmaster` 인 항목(shared_buffers 등)은 **서버 재시작**이 필요합니다.

@@ex 18-04 18-05

| 설정 | 의미 | 출발점 (전용 DB 서버 기준) |
|---|---|---|
| `shared_buffers` | PostgreSQL 전용 캐시 | 메모리의 25% |
| `effective_cache_size` | OS 캐시 포함 예상 캐시 (계획용) | 메모리의 50~75% |
| `work_mem` | 정렬·해시 작업당 메모리 | 4~64MB (동시 작업 수 고려) |
| `maintenance_work_mem` | VACUUM, 인덱스 생성용 | 256MB~1GB |
| `max_connections` | 최대 접속 수 | 기본 100, 많으면 커넥션 풀(PgBouncer) |

## VACUUM 과 ANALYZE

14장 MVCC 에서 UPDATE/DELETE 는 옛 버전(dead tuple)을 남긴다고 했습니다. VACUUM 은 이 공간을 재사용 가능하게 정리하고, ANALYZE 는 옵티마이저가 쓰는 통계를 갱신합니다. 평소에는 **autovacuum** 이 자동으로 실행합니다.

@@ex 18-06 18-07

| 명령 | 하는 일 | 잠금 |
|---|---|---|
| `VACUUM` | dead tuple 정리, 공간 재사용 표시 | 읽기·쓰기 허용 |
| `VACUUM ANALYZE` | 정리 + 통계 갱신 | 읽기·쓰기 허용 |
| `VACUUM FULL` | 테이블을 새로 써서 디스크 크기 축소 | **테이블 전체 잠금** (운영 시간 피함) |
| `ANALYZE` | 통계만 갱신 (대량 입력 직후 권장) | 읽기·쓰기 허용 |

> [!TEACH] VACUUM 을 비유로
> “식당에서 손님이 나간 테이블(dead tuple)을 치우는 직원이 autovacuum” 이라고 설명하면 잘 전달됩니다. 치우지 않으면 새 손님을 앉힐 자리가 없어 가게(테이블 파일)를 계속 넓혀야 하고(bloat), 오래 앉아 있는 손님(긴 트랜잭션)이 있으면 그 주변은 치울 수 없습니다.

## 확장 (Extension)

| 확장 | 기능 |

| `pgcrypto` | 해시, 암호화 (`crypt`, `gen_salt`, `digest`) |

| `pgvector` | 벡터 유사도 검색 (AI 임베딩, 별도 설치) |

## 백업과 복구

| 방식 | 도구 | 특징 |
|---|---|---|
| 논리 백업 | `pg_dump` / `pg_dumpall` | SQL 또는 아카이브 파일. DB·테이블 단위, 버전 간 이전 가능 |
| 물리 백업 | `pg_basebackup` | 데이터 디렉터리 전체 복사. 대용량에 빠름 |
| 시점 복구(PITR) | 물리 백업 + WAL 보관 | 특정 시각으로 되돌리기 (실수로 DELETE 하기 직전 등) |

다음 명령은 psql 이 아니라 **명령 프롬프트/터미널**에서 실행합니다. (PostgreSQL 18.6 에서 실행 확인)

```
:: 1) 사용자 지정 형식(-F c, 압축)으로 백업 - 가장 권장
pg_dump -U postgres -d shop -F c -f shop.dump

:: 2) 새 DB 를 만들고 복구
createdb -U postgres shop_restore
pg_restore -U postgres -d shop_restore shop.dump

:: 3) 일반 SQL 파일로 백업 (psql -f 로 복구, 내용을 눈으로 확인 가능)
pg_dump -U postgres -d shop -f shop.sql
psql -U postgres -d shop_restore2 -f shop.sql

:: 4) 특정 테이블 구조만 / 백업 파일 목록 보기 / 롤 등 전역 객체 백업
pg_dump -U postgres -d shop --schema-only -t customers
pg_restore -l shop.dump
pg_dumpall -U postgres --globals-only -f globals.sql
```

> [!TIP] DBeaver 에서 백업/복구
> 데이터베이스(또는 스키마) 우클릭 → **Tools → Backup** / **Restore** 는 내부적으로 위의 `pg_dump` / `pg_restore` 를 실행하는 화면입니다. 처음 실행할 때 PostgreSQL 설치 폴더의 `bin`(예: `C:\Program Files\PostgreSQL\18\bin`)을 **Local Client** 로 지정하라는 창이 뜹니다. 형식은 Custom(= `-F c`)을 고릅니다. 명령어를 먼저 가르치고, GUI 는 같은 작업의 단축 방법으로 보여 주세요.

> [!WARN] 백업은 복구해 봐야 백업이다
> 백업 파일이 있어도 복구 절차를 연습하지 않으면 장애 때 쓸 수 없습니다. 정기적으로 다른 서버에 복구해 보는 것, 백업 파일을 DB 서버와 다른 곳에 보관하는 것을 강조하세요. 클라우드 관리형 DB(RDS 등)는 자동 백업과 PITR 을 제공합니다.

## 데이터 가져오기 / 내보내기

**DBeaver (수업 기본)**

- 내보내기: 테이블 우클릭(또는 결과 그리드 우클릭) → **Export Data** → CSV / Excel(XLSX) / JSON / SQL INSERT 등 형식 선택 → 인코딩 `UTF-8`, 헤더 포함 여부, 저장 폴더 지정 → Proceed.
- 가져오기: 대상 테이블 우클릭 → **Import Data** → CSV 선택 → 파일 지정 → 열 매핑(Columns mapping) 확인 → Proceed. 날짜 형식과 NULL 표시 문자열을 확인합니다.

**psql / SQL**

| 명령 | 파일 위치 | 권한 |
|---|---|---|
| `COPY 테이블 TO/FROM '경로'` | **DB 서버**의 파일 | superuser 또는 pg_read/write_server_files |
| `\copy 테이블 TO/FROM '경로'` | **psql 을 실행한 PC** 의 파일 | 일반 사용자 가능 |

18-10 은 psql 메타 명령이라 DBeaver 에서는 실행되지 않습니다. 명령 프롬프트에서 `psql -U postgres -d shop` 으로 접속해 실행하거나, 위의 DBeaver 마법사로 같은 작업을 합니다.

@@ex 18-10

> [!TIP] 엑셀 CSV 를 가져올 때
> 엑셀에서 “CSV UTF-8” 형식으로 저장해야 한글이 깨지지 않습니다. 날짜 형식, 천 단위 쉼표, 빈 칸(NULL)을 미리 정리하고, 먼저 모든 컬럼이 TEXT 인 임시 테이블로 가져온 뒤 SQL 로 정제해 넣는 방법이 안전합니다.

## 정리

- 모니터링은 pg_stat_activity, pg_stat_user_tables, pg_stat_statements 부터.
- dead tuple 은 autovacuum 이 정리, 대량 변경 후에는 ANALYZE.
- 백업은 `pg_dump -F c`, 복구는 `pg_restore`. 복구 연습까지가 백업이다.
